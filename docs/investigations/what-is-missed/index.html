Investigations · 3 of 7 · Swarm Traces incident, July 2026

What an investigator would still miss

The people who ran the incident published what they found. We checked each finding against the public release. 15 of 41 cannot be seen in it at all.

13 claims · 5 records cited · 411 words. Select a marked claim to see the evidence behind it.

Checking against the insiders

METR, OpenAI and Hugging Face saw the whole incident: the message board, the transcripts, the servers. The public release holds less. Evidence 1: We listed 41 findings, from their reports and from the authors of the release, and looked for each one in the records.1 Evidence 2: The tool recovers 11, finds part of 15, and cannot see 15.2 All of the invisible ones come from the incident reports. The grading used a tolerance of one hour for a time, fixed before the run; several of the findings are the release authors' own claims searched in the same data, so this is not an independent test.

The start and the end are missing

Evidence 3: Hugging Face recovered attacker actions from Jul 9 02:28.3 Evidence 4: The earliest record the tool can date is on Jul 9 13:29, 11.0 hours later.4 Evidence 5: OpenAI's monitoring flagged the activity on Jul 19 12:03. The dated records stop on Jul 13 15:50.5 The build-up and the detection both fall outside the window.

Most records have no name

Evidence 6: 77,626 of the 91,037 actions come from anonymous runs: no token and no name.6 The tool tries to link each run to a named actor through rare material they share. Evidence 7: 92% of the anonymous runs stay unattributed.7 The reports count agents. Evidence 8: The release cannot. It has tokens and names, not agents.8

The board is almost empty

The agents talked through a message board on a package registry. Its contents are not in the release. Only the folder names that the code mentions are visible. Evidence 9: The tool sees 503 board folders.9 Evidence 10: In only 1 of them does it see both a writer and a reader.10 Evidence 11: That one is a single token that reads its own folder and then writes it.11 Evidence 12: No board folder shows a read after another actor's write: the one board delivery an earlier version counted was a run creating a folder and another run fetching a random name, and it is no longer counted.12

What would close the gaps

Evidence 13: The tool ranks what to collect next time by how much each missing field leaves open.13 First: An actor id on every record (which agent run wrote it). Second: The contents and the write and read log of every shared place (here, the board). Third: A timestamp on every record (server clock, UTC, to the second). None of these is exotic. Until they exist, a count of agents who coordinated, read from this release, is a floor and not a measurement.
