Who failed, and when? The tool against someone else's labels

Who&When holds 184 failed runs of real agent teams, each with a human label of the agent and the step that caused the failure. The tool finds who talks to whom. It does not find who failed.

9 claims · 3 records cited · 433 words. Select a marked claim to see the evidence behind it.

A dataset with the answer written down

Every accuracy number for this tool used to come from our own simulator. Who&When is someone else's data: Evidence 1: 184 failed runs of real agent teams1, and for each one a person wrote down which agent made the decisive mistake and at which step. Nobody on this project made those labels.

The runs are not attacks and they are not swarms. Each is one small team working on one task. Evidence 2: No message carries a time2, only its place in the order. Loaded as logged, the tool cannot run its replay, and it leaves every logged message out of its graph.

Who talked to whom

In the hand-crafted runs the log names the recipient of each instruction. Evidence 3: 689 messages are addressed this way3. With the recipients kept, the tool lists all of them as direct messages once the records have a clock. That checks our reader. It is not an accuracy.

Then we took the recipients away. The tool saw who spoke, in what order, and the text. Evidence 4: It still found 91 of the 92 sender-recipient pairs4. It found far fewer of the single messages: Evidence 5: 62 of 6895. It counts each write once per reader, so it learns that the orchestrator talks to the web surfer, and not which instruction was which.

Who failed

The tool has no feature that names a culprit. We read its flags as blame by rules fixed before any score was computed. Evidence 6: The record of its first warning sign is by the labelled agent in 54 of 184 runs6, and chance is 29%. Evidence 7: Naming the agent with the most records does better: 727. The dataset's authors report 54% for their best method, a language model that reads the whole log.

One run shows why. Evidence 8: The annotators marked a click by the web surfer that landed on an unrelated page8. The tool's first sign in that run is the orchestrator's opening plan, because that is where a second speaker first appears. A tool that looks for shared places, carried tokens and harmful actions has no reason to look at a wrong click.

False alarms

Every run here is benign in the tool's sense: nothing is hidden and nobody is attacked. Evidence 9: On an order-only clock the Alert rule fired in 181 of 184 runs9. It fires when a team talks. That is what it measures: information flow, not malice.

The steps of the hand-crafted runs come from Magentic-One, and the others from group chats built by an algorithm. Credit for the data and the labels is in the source line below and beside each excerpt.
