Seven frameworks, no attack: how often the alarms fire

MAST-Data holds 1,642 runs of seven agent frameworks doing ordinary tasks. None is an attack. The Alert rule fired in 1,567 of the 1,640 we could read.

13 claims · 2 records cited · 393 words. Select a marked claim to see the evidence behind it.

Real teams, nothing to hide

The audit of this project asked for real benign traffic from teams of agents. MAST-Data has it: Evidence 1: 1,642 runs of seven agent frameworks1 on ordinary tasks such as writing a small program or answering a question. Each run comes with a mark for each of fourteen kinds of task failure. Evidence 2: The marks were made by a language-model judge, not by people2, so we use them only as a rough split between runs that failed and runs that did not.

Each framework logs in its own layout, as one block of text. Our reader keeps the agent turns and leaves the other log lines out. Evidence 3: 24,461 of the 37,805 records carry a time the framework printed3. The rest have only their order.

The alarms

None of these runs is an attack. Evidence 4: The Alert rule fired in 1,567 of 1,6404. It asks for two kinds of coordination sign, and a team that takes turns in one conversation shows two within its first few messages. Evidence 5: The Watch rule fired in 3485: words such as token, secret and delete are ordinary in programming work. Evidence 6: The hourly volume baseline fired in 06, and that says nothing, because it needs half a day of history and a run lasts minutes.

A real clock does not change this. Evidence 7: In ChatDev, which prints its times, the Alert rule fired in 330 of 330 runs7.

Who talked to whom

Three of the frameworks name the recipient of a message in the log. Evidence 8: 13,441 messages are addressed8. With the recipients removed, Evidence 9: the tool found 2,242 of the 2,800 sender-recipient pairs9 from speaking order alone. Evidence 10: In one run a supervisor asks a music agent a question10, and the tool links the two because the agent speaks next. It cannot tell which of several instructions an answer belongs to: Evidence 11: in ChatDev it found 490 of 12,500 single messages11.

Failure is not harm

Evidence 12: The Watch rule fired on 26% of the runs marked as failed and 6% of the clean ones12. Most of that gap is the mix of frameworks. Evidence 13: 311 of the 400 clean runs come from one framework13, and there the rule almost never fires on any run. The rules were written for attacks. Nothing here shows that they see task failure.
