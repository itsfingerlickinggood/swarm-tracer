The sign that looked early

In our first simulated swarms one sign seemed to fire hours before the first harm: two identities using the same place. With place names in code comments ignored it fires after the first harm, on an independent generator it never fires, and on the real incident it came late. Here is what each result rests on.

10 claims · 4 records cited · 487 words. Select a marked claim to see the evidence behind it.

The sign

Agents that work together need somewhere to leave things. A dataset. A folder. A page. Evidence 1: The sign fires the first time two different identities use the same named place.1 It does not need a message. It does not need to know who wrote and who read. Two names on one place is enough.

In the simulator it looked early, then it did not

We froze the definitions of every sign. Then we generated swarms the signs had never seen. An earlier version of this page said the sign fired almost six hours ahead. An audit found why: the simulator writes notes that name a place at random times, and the sign counted a place named in a code comment. With comment-only mentions ignored, Evidence 2: the shared-place sign fired in 90 of 90 coordinated swarms2 but Evidence 3: it fired a median 1.4 hours after the first harmful action, and only 0.4 hours before the first delivery.3 Evidence 4: It fired in 0 of 30 benign swarms.4

Read this with care. Evidence 5: These swarms come from our own simulator.5 We wrote the generator and we wrote the sign. On a second generator, written independently, the sign did not fire in any coordinated swarm, because those swarms coordinate through ordinary dataset names. We had no real benign traffic from many agents to test for false alarms. So the sign is not an early warning even in a world we built.

On the real incident it was late

The Swarm Traces release is real. It has no truth file, so nobody can say how early a sign should have been. We can only say when it fired. Evidence 6: The first harmful sign fires on Jul 9 13:29: an anonymous run reads a folder on the package registry.6 Evidence 7: The shared-place sign fires on Jul 11 20:05, more than two days later.7 cred 169 had used a place name. Now cred 170 used it too. Evidence 8: At that point 50% of the dated harm was still to come.8 Half of it had already happened. Plain baselines (the first new host, the first search for secrets, a distinct-actor alarm, a volume alarm with a short history) all fired earlier than this sign.

And the two identities were probably one agent

Evidence 9: cred 169 and cred 170 are two tokens of the same estimated agent.9 One agent using its own place under two tokens is not two agents meeting. Evidence 10: Counted by estimated agent the sign moves to Jul 12 18:22, with 5% of the harm still to come.10

What to take from it

The sign is cheap and it needs little data. In simulation it fires after the first harm, on a second generator it does not fire, and on the one real incident we could test it came late, and its first hit was one agent seen twice. We would not ship it as an alarm on this evidence. The lead of almost six hours we published earlier is withdrawn.
